# Известные баги и риски

В текущем состоянии кодовой базы (по результатам глубокого сканирования) существуют следующие известные проблемы и риски.

## 1. Риски гонки при автосохранении (Race Conditions in Autosave)
В редакторе `core-api.js` логика автосохранения (`pushCurrentSnapshotToHistory` и `captureSnapshot`) базируется на таймерах и диффах между предыдущим состоянием. Если пользователь быстро переключает заметки, возможно, что отложенное автосохранение отработает для предыдущей заметки, перезаписав её новым `id` (или бросит ошибку, если стейт уже очищен функцией `close()`).

## 2. Проблемы с восстановлением рисунков (Drawing Loader)
В `core-api.js` при открытии заметки загружаются `pageDrawingsRevision`. Поскольку используется `dataURL`, при больших рисунках Canvas перерисовывается. При быстрых скроллах или переключениях страниц (многостраничная заметка) возможна рассинхронизация между тем, какой рисунок загружен на слой Canvas, и текущей страницей текста.

## 3. UI Hydration и DOM обзерверы
- В `core-api.js` используется `MutationObserver` на элементе `contentElement` (`state.observer.observe(...)`). Он отключается при закрытии заметки, но в `renderState` есть блокировка `state.isRenderingState = true`. Если отрендерить заметку с некорректным HTML (например, скопированным из внешнего редактора), observer может начать циклично перестраивать дерево (Infinite loop risk), если скрипты нормализации форматирования срабатывают рекурсивно.

## 4. Пагинация и кэширование
В `load-app.js` пагинация обрабатывается на клиенте с помощью `PaginationService.getVisibleNotesForRender`. Однако, логика `searchQuery` фильтрует заметки только из загруженного пула (`queriedNotes`). Если у пользователя 10 000 заметок, клиентский фильтр не найдет заметки, которые еще не были загружены с сервера (offset pagination с `startAfterId`).

## 5. Ошибки Offline режима (Service Worker)
Механизм PWA пытается кешировать файлы (манифест и `sw.js`). Но `createNetworkLifecycleController` в `load-app.js` при возобновлении сети вызывает `sessionService.startUserSession(user, { forceResubscribe: true })`. Если Supabase Auth токен протух за время офлайна, этот вызов тихо умрет, и пользователь не сможет синхронизировать написанный в офлайне текст (потеря данных).
