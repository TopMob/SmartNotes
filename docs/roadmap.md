# Roadmap развития проекта

Основываясь на текущем состоянии архитектуры и выявленном техническом долге, дальнейшее развитие проекта должно фокусироваться на стабилизации фронтенд-движка, улучшении AI интеграции и решении UI проблем.

## Q1: Стабилизация и Рефакторинг Фронтенда
- **Типизация:** Постепенное внедрение TypeScript (или JSDoc) в `public/js/`. Начать с `core-state.js` и моделей данных (заметки, папки).
- **Модульность:** Разбить монолитные файлы (например, `load-ui-core.js`) на небольшие изолированные компоненты с использованием современных сборщиков (Webpack/Vite), чтобы уйти от прямого подключения `type="module"` в браузере, так как файлов уже более 20.
- **Очистка легаси:** Удалить неиспользуемые переменные и глобальные экспорты (перевести `window.SmartNotesEditor` в нормальный ES import для модулей, которые его используют).

## Q2: Улучшение AI и Базы Данных (Векторный поиск)
- **Полный векторный поиск (Vector Search):** Сейчас AI просто проставляет скрытые теги. В будущем необходимо интегрировать `pgvector` в Supabase. При вызове AI генерировать эмбеддинги (`embeddings`) для текста заметки и сохранять их в БД, что позволит реализовать семантический поиск по всей базе, а не только фильтрацию на клиенте (решение бага с пагинацией).
- **Улучшение провайдеров:** Переработать файл провайдеров, перенести конфигурацию моделей (temperatures, chunking rules) в настройки пользователя в UI, а не хранить их на бэкенде.

## Q3: Развитие кастомного редактора
- **Коллаборация (Real-time):** Сейчас шаринг работает на уровне базы (RLS), но редактор не поддерживает одновременное редактирование (CRDT). Переход на архитектуру Yjs для редактора и Canvas.
- **Оптимизация рисования:** Вместо `dataURL` снимков (`pageDrawings`), сохранять векторные координаты штрихов (JSON формат). Это ускорит загрузку и улучшит качество при зуме.

## Q4: Инфраструктура и DevOps
- **Тесты:** Внедрить Playwright тесты для проверки UI (рисование, вставка ссылок). На данный момент используются только базовые Node.js/JSDOM тесты.
- **Умное кэширование (Offline-first):** Интегрировать IndexedDB для полноценного хранения заметок в офлайне с отложенной синхронизацией, чтобы предотвратить потерю данных (как описано в known-bugs).
