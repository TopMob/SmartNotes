# Архитектура проекта

SmartNotes использует гибридную архитектуру, где серверная часть (backend) реализована на Next.js App Router (с API роутами), а клиентская (frontend) — на кастомном движке (Vanilla JS) и CSS переменных.

## Основные компоненты

### 1. Backend (Next.js + Supabase)
Серверная часть расположена в `app/api/` и использует Supabase как базу данных и провайдера аутентификации.

- **Supabase Auth & Sessions (`app/api/supabase/`):**
  Авторизация обрабатывается через `/auth`, получение сессии через `/session`. Имеется защита роутов и синхронизация профилей пользователей.
- **Данные и RLS:**
  Доступ к данным (заметки в `/notes`, папки в `/folders`, права доступа `/notes/share` и настройки `/settings`) контролируется на уровне Supabase RLS. Клиент запрашивает данные напрямую (через Supabase JS клиент в браузере), а серверные роуты используются для административных задач и интеграции с AI.
- **Supabase Admin Singleton (`lib/supabase/admin.ts`):**
  Реализован синглтон для обхода RLS, использующий `Service Role Key` для выполнения специфичных серверных задач.
- **AI Backend (`app/api/analyze/`):**
  Отдельная API ветка для обработки заметок через LLM провайдеров (подробнее в `ai-engine.md`).

### 2. Frontend (Кастомный движок на Vanilla JS)
Все исходники клиентской части находятся в папке `public/js/`. Приложение не использует React на клиенте для отображения заметок — страница (`app/page.tsx`) загружает статические скрипты:
- **`load-app.js`, `load-engines.js`, `load-foundation.js`, `load-services.js`**: Ядро приложения, система состояний (`StateStore`), события (`EventBus`) и интеграция с Supabase (`SessionService`).
- **Собственный редактор (`public/js/editor/`)**: Разделен на движки (`core-engine.js`, `feature-engine.js`, `input-engine.js`) для управления вводом, автосохранением (`core-autosave.js`), историей и отображением контента.
- **Взаимодействие компонентов**:
  Всё взаимодействие осуществляется через подписки на `EventBus` и `StateStore`, что минимизирует перерисовки (hydration risks отсутствуют для заметок, так как Next.js не управляет этой частью DOM).

### 3. Модель данных (Схема БД)
Основная схема базы данных включает следующие сущности:
- **Заметки (Notes)**: Хранят `title`, `content`, `tags`, `folderId`, `pageDrawings` и метаданные AI.
- **Папки (Folders)**: Поддерживают структуру, содержат статус архивации/скрытости.
- **Доступы (Permissions)**: Реализованы таблицы доступов для шеринга (разделение ролей: `viewer`, `editor`).
- **Настройки (Settings)**: Индивидуальные параметры темы и UI для пользователей.

## Поток данных (Data Flow)
1. Пользователь загружает приложение (Next.js возвращает статический HTML с подключенными JS файлами из `public`).
2. Аутентификация: `SessionService` (используя скрипты в `public/js/core/`) синхронизирует состояние пользователя с Supabase, вызывая при необходимости `/api/supabase/session`.
3. Загрузка данных: `NotesQueryService` и другие сервисы делают прямые запросы к Supabase (используя клиент из `public/vendor/supabase.js`) для загрузки заметок и папок.
4. Редактирование: Редактор (`window.SmartNotesEditor`) отлавливает изменения и периодически запускает автосохранение (`queueSnapshot`), отправляя диффы в базу данных.
