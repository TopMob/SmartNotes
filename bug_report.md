# Отчет об ошибках: Модуль авторизации (Auth)

## 1. Уязвимость SSRF / Открытый прокси-сервер (Open Proxy)
**Bug:** API маршрут позволяет отправлять запросы к произвольным эндпоинтам Supabase, потенциально выступая в качестве открытого прокси-сервера или раскрывая внутреннюю логику маршрутизации.
**Location:** `app/api/supabase/auth/route.ts`, строки 18-36
**Cause:** Переменная `path` извлекается напрямую из тела запроса (`body.path`) и конкатенируется в `buildSupabaseAuthUrl`. Хотя `buildSupabaseAuthUrl` удаляет начальные слеши, функция не ограничивает путь строго ожидаемыми эндпоинтами авторизации. Это позволяет пользователю обращаться к любому Supabase API по пути `/auth/v1/` или потенциально обходить ограничения.
**Fix Suggestion:** Реализовать строгий "белый список" (whitelist) разрешенных путей аутентификации (например, `['token', 'user', 'recover']`) и отклонять любые пути, не входящие в него, до вызова `fetch`.

## 2. Уязвимость открытого перенаправления (Open Redirect)
**Bug:** Страница обратного вызова (callback) допускает перенаправление на непроверенные пути, что может способствовать фишинговым атакам.
**Location:** `app/auth/callback/page.tsx`, строки 12-17 (функция `buildRedirectUrl`)
**Cause:** Функция проверяет, начинается ли `next` с `/` и не начинается ли с `//` для предотвращения перенаправлений по абсолютным URL, но злоумышленник всё равно может обойти это, используя вариации вроде `/\example.com` или другие граничные случаи парсинга URL в зависимости от того, как браузер интерпретирует строку в `window.location.replace()`.
**Fix Suggestion:** Использовать объект `URL` для разбора и проверки пути перенаправления относительно базового URL приложения (`window.location.origin`), гарантируя точное совпадение источника (origin), либо использовать встроенные в Next.js утилиты маршрутизатора и проверки путей.

## 3. Ошибка запасного метода авторизации (Необработанная ошибка / Promise Rejection)
**Bug:** Функция `callAuthFallback` плохо обрабатывает ошибки вызова `fetch`, что может привести к сбою всего процесса авторизации на клиенте, если запасной серверный маршрут недоступен.
**Location:** `public/js/core/supabase.js`, строки 46-65 (функция `callAuthFallback`)
**Cause:** Конструкция `response.json().catch(() => ({}))` игнорирует ошибки разбора, но если сетевой запрос полностью завершается неудачно (например, ошибка CORS, сервер недоступен), вызов `await fetch()` выбрасывает исключение, которое не перехватывается внутри `callAuthFallback`.
**Fix Suggestion:** Обернуть весь вызов `fetch` в блок `try...catch` внутри `callAuthFallback` и возвращать структурированный объект `{ data: null, error: ... }` при сбое сети, вместо того чтобы позволять promise завершаться с необработанным исключением.

## 4. Состояние гонки (Race Condition) при синхронизации профиля
**Bug:** Callback авторизации запускает синхронизацию профиля асинхронно без ожидания (await), что может привести к неполным данным профиля, если страница перенаправит пользователя до завершения синхронизации.
**Location:** `app/auth/callback/page.tsx`, строки 99-101
**Cause:** Создается promise `syncProfile(session.access_token).catch(...)`, но его выполнение не ожидается (не используется `await`) перед вызовом `clearCallbackUrl` и `window.location.replace(nextPath)`. Браузер может отменить выполняющийся POST запрос к `/api/supabase/session` при переходе со страницы.
**Fix Suggestion:** Ожидать (`await`) вызов `syncProfile` перед перенаправлением или использовать `navigator.sendBeacon` (хотя в настройках `fetch` используется `keepalive: true`, ожидание гарантирует завершение и позволяет избежать зависимости от реализации keepalive в браузерах во время навигации).
